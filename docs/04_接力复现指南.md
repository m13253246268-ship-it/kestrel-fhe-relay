# 28 层全同态 LLM 推理 · 接力复现指南（社区接力版）

> 面向对象：想帮忙把 Qwen3-VL-2B 的 RNS-CKKS 全密文推理链**接着往下跑**的人。
> 本文只讲"怎么接着算"，不讲原理（原理文档在主项目 `资料/FHE同态加密推理技术介绍.md`，**未随本仓分发**）。
> **工具清单与逐参数用法**见 [`05_工具说明.md`](./05_工具说明.md)。
> 版本：2026-09-14 · 作者自测环境：AMD Ryzen 7 9800X3D (8C/16T) · Windows 11 24H2 · MinGW-W64 gcc 16.1.0

---

## 0. 一页纸摘要（TL;DR）

| 项目 | 内容 |
|---|---|
| 目标 | 单机纯 CPU（无 GPU）、纯 C11、零第三方依赖，把 Qwen3-VL-2B 的 28 层 Transformer **全程在密文上**跑完并输出 logits |
| 现在到哪了 | **第 0–4 层（5 层）已打通**：每层 `lay` 跳 `RESULT=PASS`，每层 `boot` 刷新跳 `BOOT=PASS`（本轮从种子重跑，见 §8） |
| 还差什么 | **链上的第 5–25 层**（接力链停在 `u4r112`）。尾部 26–27 + `fin` 已用**另一条支线**（从明文种子进 L26、**绕过 5–25 层**）单独跑通，见 §8.1 |
| 单层成本 | **lay ≈ 33 min + boot ≈ 72–81 min ≈ 1.8 h/层**（9800X3D、4 线程实测） |
| 为什么需要接力 | 单机全链 ≈50 h，纯 CPU；把它切成"每人几层"就能几天内跑完 |
| 每层交接物 | 该层输出 **8 个密文文件 `u{L}r112_{t}_{h}.ct`（约 28 MB）+ `sk.bin`**，别人拿到即可从 `L+1` 继续 |
| 判据 | `lay` 看日志末尾 `RESULT=PASS`；`boot` 看 `BOOT=PASS`。**段级 FAIL 不算数**，见 §7 |

## 0.1 本项目主张的边界（**先读这条**）

我们**只主张**下面这一件事，其余一律不作为既有结论：

| 主张 | 状态 |
|---|---|
| ✅ **前 5 层（层 0–4）在纯 CPU 上可复现、可独立验证**：逐层 `lay` 判据 `RESULT=PASS`，逐层 `boot` 刷新判据 `BOOT=PASS`（每次刷回满链 `out np=2083`）；同一源码在 x86-64 与 aarch64 逐系数位级一致 | **本仓库负责** |
| ✅ **尾部（层 26–27 + `fin`）也算得对**：从明文种子直接加密进 L26（**绕过 5–25 层**），五步全 `PASS`，`fin` 的 logits top1 **4/4** 与参考一致 | **本仓库负责**（见 §8.1） |
| ❌ 「28 层全链跑通」 | **不主张**——这是**社区接力目标**，不是已有结果 |
| ❌ 密码学安全性 / 性能优越性 | **不主张**（见 §9） |

> 因此本指南的定位是：**把"前 5 层可复现、可验证"这件事讲透、做扎实**，并把第 5–27 层作为开放接力项交出去。
> 任何人接手后跑出的第 6 层及以后的结果，属于**他的贡献**，不能倒填成本项目已有结论。

## 1. 你要准备什么

### 1.1 硬件
- x86-64 或 ARM64（RK3588 已验证与 x86 **逐系数位级一致**，差异 0 / ~1e-16）；
- 建议 ≥4 逻辑核（默认 `T23_NT=4`；8 线程绝对吞吐更高，功耗也更高）；
- 可用内存 ≥8 GB（`lay` 阶段实测工作集 ≈1.0 GB；`boot` 阶段模数链 `np=2100` 更大，建议多留）；
- 磁盘：**数据包约 7 GB + 模型 4.26 GB（自助生成时要）+ 每层产物 ≈28 MB**，建议留 **≥20 GB** 可用空间。

### 1.2 工具链
- 一个能编译 C11 + OpenMP 的 `gcc`（MinGW-W64 / Linux gcc 均可）；整链只依赖 `libc + libm`；
- 不需要安装任何密码学库。

### 1.3 数据包（关键，约 7 GB）
源码里**不含**权重与参考数据。两条路，任选其一：

| 路径 | 做法 | 代价 |
|---|---|---|
| **A. 自助生成（完全可复现）** | 下 `Modl/Qwen3-VL-2B-Instruct/`（`model.safetensors` 4.26 GB + `vocab.json`）+ 装 `numpy` `safetensors`，然后按主仓 `tools/preproc/README.md` §3 的顺序在仓库根依次跑：`_export_weights.py` → **`_embed4.py`** → **`_silu_mode.py`** → `_full_layers.py` → `_tail_ref.py` → `_sin_fit.py` / `_recip_fit.py` → `_adap_scale.py` | 一次 Python 预处理 |
| **B. 向作者索取现成数据包** | Issue 里要 | 传输 7 GB |

> ⚠️ **顺序不能省，有两个"缺了不报错"的文件**：
> `_embed4.py`（lay0 的明文输入）与 `_silu_mode.py`（逐层 SiLU 路径开关）产出的都是驱动**必需、
> 但缺失时不会报错**的文件——缺了它们驱动**仍会打 `RESULT=PASS`，而数值是错的**。
> 实测：层 0 缺 `silu0.bin` 时 `max|err|` = 4.2e-2 ~ 8.5e-2（超 3e-2 容差），补上后回到 1.27e-3。
> **所以判据日志不能替代数值复核**：每跑完一层都要用 `tools/relay/verify_layer.ps1`（或 `verify_layer.exe`）
> 独立复核 `max|err|`，见 §5.6 与 §7。

> **`l0/embed4.bin` 这一处曾经的缺口已补齐**：它是 lay0 的明文输入（4 个 token 的 embedding 查表结果），
> 以前没有生成脚本，只能随数据包分发。现在用 **`tools/preproc/_embed4.py`** 生成，
> 默认 `--ids 100,101,102,103`（就是已发布数据所用的 4 个 id），产出 32768 B、
> 与数据包里的 `embed4.bin` **逐字节相同**（SHA256 前缀 `c945c8fe92cc0595`，已实测复核）。
>
> `sk.bin` 也可由驱动自己生成：**先建好 `.tmp_tok/chain/`**，再跑
> `T23_PHASE=l0 T23_KEYONLY=1 .tmp_tok/t23lay.exe`，看到 `KEYONLY: sk.bin saved` 即可。
> 建目录这一步不能省：驱动用裸 `fopen` 落盘、**不会自建目录**，缺了会报 `[FAIL] sk save`
> （跑层时同理，缺了会报 `[FAIL] ct save`）。

```
.tmp_tok/
├── chain/sk.bin                 # 私钥（2 KB）—— 全链唯一，必须与权重/参考同源
├── chain/u0r112_{t}_{h}.ct      # 起点密文种子（8 个），或你接棒时的 u{L-1}r112
├── tail/w0 .. w27/              # 每层权重（gcc 读取的 .bin，每层 9 个）
├── tail/l{L}_*.bin              # 每层明文参考（校验用）
├── tail/scale{L}.bin            # 逐层自适应尺度（残差折叠除数）
├── tail/silu{L}.bin             # SiLU 逼近模式开关
├── tail/ln{L}_e1.bin / ln{L}_p1.bin / m2c{L}_e.bin / m2c{L}_p.bin
├── l0/  l1w/  l1r/              # layer0 / layer1 专用权重与参考
└── ...
```

> **数据自检（跑之前先确认）**：`.tmp_tok/chain/sk.bin`、你这一棒的输入密文、`tail/w{L}/`（9 个文件）、`tail/scale{L}.bin` 必须存在。缺一个就会在加载阶段直接报错退出。
>
> **还要单独确认这两个（它们缺了不报错，但数值是错的）**：`tail/silu{L}.bin`（每层一个，8 B；§1.3 的 `_silu_mode.py` 生成）
> 与 `l0/embed4.bin`（只有 `lay0` 用；`_embed4.py` 生成）。**别只跑上面那四项就开工。**

（上表就是数据包在仓库根下的相对布局；引擎把前缀硬编码为 `.tmp_tok/`。）

### 1.4 不想装 gcc？用预编译二进制跳过编译

本仓 **Releases** 里有 Windows x86-64 的预编译三件套（`t23lay.exe` / `t23boot.exe` / `verify_layer.exe`，

## 2. 构建（两条命令，已验证）

源码位置：`src/core/{vllm_ntt.c, vllm_ckks.c, vllm_tp.c}` + 驱动 `tools/drivers/{t23_m3p.c, t23_chain.c}`（**都在仓库里**；`.tmp_tok/` 只放数据与产物）。

> **先建工作目录**：`mkdir -p .tmp_tok .tmp_tok/chain .tmp_tok/relay`（PowerShell：
> `New-Item -ItemType Directory -Force .tmp_tok, .tmp_tok\chain, .tmp_tok\relay | Out-Null`）。
> `.tmp_tok/chain/` 是落密文的地方，**驱动不会自建**（缺了会报 `[FAIL] ct save` / `[FAIL] sk save`）；
> `.tmp_tok/relay/` 是 §4.2/§4.3 手动跑层时放日志的地方，**重定向也不会自建目录**（见 §4.2 的实测说明）；
> 两个 `-o` 也写进 `.tmp_tok/`，目录不存在时链接器会直接报 `cannot open output file .tmp_tok/t23lay.exe`。
> 输出名写 `t23lay` 即可，MinGW gcc 会自动补 `.exe`。
> （用 §4.4 的一键脚本则不用手建——脚本会自己把用到的目录准备好。）

```bash
# lay 跳（层内前向）：模数链 112 个素数
gcc -O2 -fopenmp -Wno-implicit-function-declaration \
    -I include -I include/core -I include/common \
    -DCKKS_N=2048 -DCKKS_NPRIMES=112 -DBB=32 -DGG=32 \
    src/core/vllm_ntt.c src/core/vllm_ckks.c src/core/vllm_tp.c tools/drivers/t23_m3p.c \
    -o .tmp_tok/t23lay -lm

# boot 跳（噪声刷新）：模数链 2100 个素数
gcc -O2 -fopenmp -Wno-implicit-function-declaration '-Wl,--stack,33554432' \
    -I include -I include/core -I include/common \
    -DCKKS_N=2048 -DCKKS_NPRIMES=2100 -DBB=32 -DGG=32 \
    src/core/vllm_ntt.c src/core/vllm_ckks.c src/core/vllm_tp.c tools/drivers/t23_chain.c \
    -o .tmp_tok/t23boot -lm
```

**编译期坑（都踩过）**
1. `-I` 必须同时给 `include`、`include/core`、`include/common`（`vllm_tp.c` 引用 `vllm_platform.h` 在 `common/`），只给 `include/core` 会报 `vllm_platform.h: No such file`。
2. Windows 下 `-Wl,--stack,...` 里的逗号会被 PowerShell 当成参数分隔符 → **必须给整段加引号** `'-Wl,--stack,33554432'`，或用 `cmd /c` 执行。
3. `boot` 用 `np=2100`，MinGW 默认栈会溢出（`0xC00000FD`）→ 加 `-Wl,--stack,33554432`。

## 3. 密文链协议：一层 = 两跳

每一层 `L` 要跑**两跳**，产物都落在 `.tmp_tok/chain/`，每跳产生 **8 个 `.ct`**（4 个 token × 2 个密文分量）：

```
seed             : chain/u0r112_{t}_{h}.ct            （起始种子，明文起点加密后刷新而来）
lay{L}  (前向)   : u{L-1}r112_{t}_{h}.ct  ──▶  u{L}_{t}_{h}.ct         判据 RESULT=PASS
boot{L} (刷新)   : u{L}_{t}_{h}.ct        ──▶  u{L}r112_{t}_{h}.ct     判据 BOOT=PASS
```

- `lay` 用密码学算完这一层的 RMSNorm → QKV → Attention → O → SwiGLU MLP → 残差，输出"噪声快用完"的密文 `u{L}`；
- `boot` 做一次完整 bootstrapping（ModRaise → CoeffToSlot → EvalMod/sin 折叠 → SlotToCoeff），把噪声预算**刷新回满链**，输出 `u{L}r112`，供下一层继续吃深链。

> 层号从 0 起：本仓库现有记录是 **lay0..lay4**（层 0..4），交接点是 `u4r112`。接棒者从 **lay5** 开始。

## 4. 跑一层：完整命令模板

### 4.1 环境变量（驱动靠它们选择行为）

| 变量 | 作用 | 取值示例 |
|---|---|---|
| `T23_PHASE` | 阶段 | `lay` / `boot` / `fin` |
| `T23_LAY` | 中间层号（仅 `lay`） | `5` |
| `T23_BI` / `T23_BO` | boot 的输入/输出前缀（仅 `boot`） | `u5` / `u5r` |
| `T23_E2EMODE` | 端到端验收模式（忽略参考偏离导致的段级 FAIL） | `1` |
| `T23_NT` | 线程数 | `4` |

### 4.2 Windows / PowerShell（本机验证过）

```powershell
cd <仓库根>

# 日志目录必须先建：cmd 的 > 重定向和驱动一样不会自建目录
New-Item -ItemType Directory -Force .tmp_tok\relay | Out-Null

# ---- 第 5 层的 lay 跳 ----
$env:T23_PHASE="lay"; $env:T23_LAY="5"; $env:T23_E2EMODE="1"; $env:T23_NT="4"
# 用 cmd 做重定向：保证日志按字节落盘，不被 PowerShell 转码
cmd /c "`.tmp_tok\t23lay.exe` > `.tmp_tok\relay\lay5.out` 2> `.tmp_tok\relay\lay5.err`"
Select-String -Path .tmp_tok\relay\lay5.out -Pattern 'RESULT=PASS'   # 有匹配 = 通过

# ---- 第 5 层的 boot 跳（刷新）----
$env:T23_PHASE="boot"; $env:T23_BI="u5"; $env:T23_BO="u5r"
cmd /c "`.tmp_tok\t23boot.exe` > `.tmp_tok\relay\boot5.out` 2> `.tmp_tok\relay\boot5.err`"
Select-String -Path .tmp_tok\relay\boot5.out -Pattern 'BOOT=PASS'   # 有匹配 = 通过
```

> ⚠️ **`.tmp_tok\relay` 不存在时，上面的重定向是"静默失败"**（实测，不是理论）：
> cmd 只会往 stderr 打一行「系统找不到指定的路径。」，**日志文件根本不生成，而 `%ERRORLEVEL%` 仍是 0**，
> 接着 `Select-String` 才报路径不存在——很容易被误判成"这层算挂了"。
> 同理，`.tmp_tok/chain/` 不存在时驱动会报 `[FAIL] ct save`（§2 已说）。**这两个目录都先建好。**

### 4.3 Linux / macOS / RK3588（bash）

```bash
cd <仓库根>                                   # 必须在仓库根：驱动内部路径硬编码为 .tmp_tok/...
mkdir -p .tmp_tok/chain .tmp_tok/relay        # 日志目录同样不会自建
T23_PHASE=lay  T23_LAY=5 T23_E2EMODE=1 T23_NT=4 .tmp_tok/t23lay  > .tmp_tok/relay/lay5.out  2> .tmp_tok/relay/lay5.err
T23_PHASE=boot T23_BI=u5 T23_BO=u5r    T23_NT=4 .tmp_tok/t23boot > .tmp_tok/relay/boot5.out 2> .tmp_tok/relay/boot5.err
grep -q RESULT=PASS .tmp_tok/relay/lay5.out   && echo "lay5 PASS"
grep -q BOOT=PASS   .tmp_tok/relay/boot5.out  && echo "boot5 PASS"
```

> 二进制在 `.tmp_tok/` 下（§2 的 `-o` 目标），不是仓库根的 `./t23lay`；
> **也不要 `cd .tmp_tok` 再跑**——驱动把数据路径写成 `.tmp_tok/...`，换目录会去读 `.tmp_tok/.tmp_tok/...` 全部加载失败。

### 4.4 一键脚本（推荐）

仓库自带 `tools/relay/rerun5_lay_boot.ps1`，可指定层范围、自动构建、断点续跑、落 `timing.tsv`：

```powershell
# 跑 5..9 层（每层 lay+boot），已有产物的层自动跳过
powershell -NoProfile -ExecutionPolicy Bypass -File tools/relay\rerun5_lay_boot.ps1 -From 5 -To 9
```

日志与汇总落在 `.tmp_tok/relay_rerun/`：`master.log`（时间线）、`timing.tsv`（逐层耗时/状态）、`lay{L}.out`/`boot{L}.out`（原始日志）、`meta.txt`（机器元数据）。

> **日志目录口径**：一键脚本写 `.tmp_tok/relay_rerun/`，§4.2/§4.3 手动跑则写 `.tmp_tok/relay/`——
> 两者不通用，找日志/`grep` 判据时别找错目录。

> 脚本有三个必须遵守的工程约定，自己写脚本时也照做：
> ① `.ps1` 若含中文注释，**必须存成 UTF-8 with BOM**（PowerShell 5.1 否则按 ANSI 读，会报"意外的标记 }"）；
> ② 子进程输出用 `cmd /c "... > out 2> err"` 重定向，别用 PowerShell 管道（会把 UTF-8 中文转成乱码）；
> ③ 判据必须落在**层输出**上，见 §7。

## 5. 接力协议：怎么把结果交给下一个人

### 5.1 判定"这一层跑完了"
`.tmp_tok/chain/` 下这 8 个文件齐全即视为该层刷新完成：

```
u{L}r112_0_0.ct  u{L}r112_0_1.ct
u{L}r112_1_0.ct  u{L}r112_1_1.ct
u{L}r112_2_0.ct  u{L}r112_2_1.ct
u{L}r112_3_0.ct  u{L}r112_3_1.ct
```

### 5.2 交接包（Handoff bundle）
把下面这些东西打包上传（网盘 / Release / Issue 附件），总量很小：

| 文件 | 说明 | 大小 |
|---|---|---|
| `u{L}r112_{t}_{h}.ct` ×8 | **核心**：下一棒的输入密文 | ≈28 MB |
| `sk.bin` | 私钥（全链一致，若对方已有可不带） | 2 KB |
| `lay{L}.out` `boot{L}.out` | 判据证据（含 `RESULT=PASS` / `BOOT=PASS`）；手动跑层在 `.tmp_tok/relay/`，一键脚本在 `.tmp_tok/relay_rerun/` | 数百 KB |
| `timing.tsv` `meta.txt` | 耗时与机器元数据 | KB 级 |

命名建议：`relay_L{L}_{你的ID}_{日期}.zip`（**实操直接用 `pack_relay.ps1` 一键生成，见 §5.5**）。

> **下一个人**把 `u{L}r112_*.ct` 放回 `.tmp_tok/chain/`，用 `-From $($L+1)` 接着跑即可。

### 5.3 典型切分（供认领参考）

| 棒次 | 层范围 | 预估单机耗时 |
|---|---|---|
| ✅ 已完成 | 0 – 4 | ≈9 h（本轮重跑实测 8.94 h，见 §8） |
| 第 2 棒 | 5 – 7 | ≈5.5 h |
| 第 3 棒 | 8 – 10 | ≈5.5 h |
| … | … | … |
| 末棒 | 25 – 27 + `fin` | ≈6 h |

> 也可以只认领 1 层（≈1.8 h），交接包一样小，**任何一块算力都有用**。

### 5.4 别人怎么**独立验证**这 5 层（"技术可验证"的具体做法）

不需要相信我们的口头结论，按下面三层校验，任何一条不通过都说明有问题：

**校验①：判据自检（秒级）**
```powershell
# 逐层 lay / boot 判据必须全部命中；任一层无匹配即为真失败
foreach ($L in 0..4) {
  "lay$L  : " + ((Select-String .tmp_tok\relay_rerun\lay$L.out  -Pattern 'RESULT=PASS') -ne $null)
  "boot$L : " + ((Select-String .tmp_tok\relay_rerun\boot$L.out -Pattern 'BOOT=PASS')   -ne $null)
}
# 刷新是否真的回满链（每层每个 token/分量都应是 2083）
Select-String .tmp_tok\relay_rerun\boot*.out -Pattern 'out np=2083' | Measure-Object
```

**校验②：交接包完整性与判据（打包 + 验证闭环，见 §5.5）**
```powershell
# 把你的层范围打成可上传的包（自动生成包内 SHA256 清单与 README）
```

> 交接物是**确定性产物**：同源数据 + 同源二进制 + 相同层序 → 逐字节一致。清单一致 = 你拿到的是同一份产物，没有被替换或截断。

**校验③：跨架构位级一致（可选，最强）**
在另一台 **不同 ISA** 的机器（如 ARM64/RK3588）上重跑 `lay0`，
用同样的 `sk.bin` 解码 `u0_{t}_{h}.ct`，解密值与 x86 结果应**逐系数相同**（实测差异 0 / ~1e-16）。
这条通过，说明结论与浮点舍入顺序、与硬件无关。

**三条都过 ⇒ "前 5 层可复现、技术可验证"成立**；其中校验①、② 任何人在自己机器上都能做。

| ② | **判据** | `logs/lay*.out` 含 `RESULT=PASS`；`logs/boot*.out` 含 `BOOT=PASS` 且 `out np=2083` 恰好每层 8 次（4 token × 2 分量） |

**信任模型（必须讲清楚，别过度宣称）**
- ✅ SHA256 清单能证明：**包没被篡改、没被截断、没夹带额外文件**；判据日志与密文是**同一批**产物。
- ⚠️ 它**不能**证明"计算本身是对的"——判据日志理论上可以被伪造。
- 🔒 **防伪造的唯一办法是交叉复算**：因为流程是确定性的，**两个人独立重跑同一层，产出的 `u{L}r112_*.ct` 的 SHA256 必须逐字节相同**。所以真正的验证姿态是：
  1. 先跑 ①②③（秒级，筛掉损坏/错包）；
  2. 对关键层（如 L10、L27）**找第二个人独立复算**，比对交接物 SHA256；
  3. 若两者一致 ⇒ 该层结果可信，且不依赖任何一方的"说法"。

> 这就是"接力"相对"单机跑完"的额外价值：**每一层天然可以被独立复现与交叉证伪**。

### 5.6 准确度校验：`verify_layer` 工具（直问"算得对不对"）

§5.5 只回答了"包有没有被改"，**没有**回答"算得对不对"。`verify_layer` 补上这一环。

**原理**：`sk.bin` 解密该层密文 → 解码成实数槽位 → 与 **float32 明文前向**产生的参考 `tail/l{L}_u2_ref.bin` 逐元素对照，算 `max|err|`。
这是一条**独立于驱动 PASS 逻辑的代码路径**（自己实现解密/解码/对照），因此可作第三方复核。

**用法**
```powershell
# ① 准确度：校验 lay 输出 u{L}（默认容差 3e-2）
powershell -NoProfile -ExecutionPolicy Bypass -File tools/relay\verify_layer.ps1 -From 0 -To 4
# ② 准确度：校验 boot 刷新输出 u{L}r112
powershell -NoProfile -ExecutionPolicy Bypass -File tools/relay\verify_layer.ps1 -From 0 -To 3 -Mode boot
# ③ 位级交叉复算：两个人独立跑同一层，逐字节比对（防伪造）
.tmp_tok\verify_layer.exe -BitA u5 -BitB u5_other -L 5
# 底层程序也可单项调用
.tmp_tok\verify_layer.exe -L 4 -Dir .tmp_tok/chain -Sk .tmp_tok/chain/sk.bin -Tol 3e-2
```
依赖：数据包中的明文参考 `tail/l{L}_u2_ref.bin`（8192 个 float32 = 4 token × 2048 维）。

**工具自身的标定**（用**上一轮**数据验证，逐层吻合；与 §8 本轮重跑的差异只在小数点后第 4~5 位，属不同轮次的正常差）

| 层 | `verify_layer` 实测 max\|err\| | 驱动日志 `.tmp_tok/relay/lay{L}.out` 的对应值 | 一致 |
|---|---|---|---|
| 0 | 1.2712e-03 | 1.271e-03 | ✅ |
| 1 | 3.1467e-03 | 3.147e-03 | ✅ |
| 2 | 2.8366e-02 | 2.837e-02 | ✅ |
| 3 | 1.2284e-02 | 1.228e-02 | ✅ |
| 4 | 1.3820e-02 | 1.382e-02 | ✅ |

> 5 层全部对得上（4~5 位有效数字），说明工具与驱动等价；结论：**前 5 层 `ALL_LAYERS_VERIFY_PASS`**。

**⚠️ 一个必须记录的发现（余量并不宽裕）**
- 层 2 的 `t1 h1` 分量 `max|err| = 2.837e-02`，容差 3e-2 —— **只剩 5.8% 余量**；

## 7. 判据口径（**最容易误判的地方，务必先读**）

跑起来后日志里会同时出现 `PASS` 和大量 `FAIL`，例如：

```
[A:xnorm t0] max|err|=2.404e-01 FAIL
[C:attn  t0] max|err|=4.941e-01 FAIL
[U2 t0 h0]   max|err|=3.980e-03 PASS [E2E:ref-deviate-ok]
RESULT=PASS (0)
```

**这不是矛盾，是口径问题**——原理与量化依据见本节末尾「段级 FAIL 但最终 PASS 的原因」。项目约定：

1. **层输出判据才是判据**：一层是否通过，只看日志**末尾**的 `RESULT=PASS`（lay）或 `BOOT=PASS`（boot）：
   - `grep RESULT=PASS .tmp_tok/relay/lay{L}.out` 有匹配（用 §4.4 一键脚本时目录是 `.tmp_tok/relay_rerun/`）；
   - `grep BOOT=PASS .tmp_tok/relay/boot{L}.out` 有匹配（且日志里 `out np=2083`，说明确实刷回了满链）。
2. **`fold` 计数会随层数变化**（lay0/1 = 16，lay2 = 128，lay3/4 = 256），它与分段 FAIL 条数同步 —— 这是参考构造的一部分，不是错误。
3. **但 `RESULT=PASS` 只代表"流程走完 + 没有硬错误"，不等于数值通过。** 接力脚本设了 `T23_E2EMODE=1`，
   会把中间量的偏差降级为"仅报告、不计入 `fails`"（日志里以 `[E2E:ref-deviate-ok]` 标记），
   所以**浅层跑错 SiLU 路径也会打出 PASS**（实测 `[U2 t3 h0] max|err|=4.460e-02 FAIL [E2E:ref-deviate-ok]`
   之后照样 `RESULT=PASS (0)`）。**每层都必须用 §5.6 的 `verify_layer` 独立复核 `max|err|` 才算数。**

> 一句话：**只认行尾的 `RESULT=PASS` / `BOOT=PASS`；分段 FAIL 请无视。** 反过来，如果层输出判据 FAIL 了，那才是真问题，请把完整日志贴回 Issue。

### 段级 FAIL 但最终 PASS 的原因

跑起来后日志里会同时出现 `PASS` 和大量 `FAIL`，**这不是矛盾**。原因是两者量的不是同一件事：

| 环节 | 说明 |
|---|---|
| 段级为何 FAIL | L26/27 使用**真实 C 折叠**（`g_causal` + 实 C 折叠），中间量 `C/D/U2` 偏离真值**属预期**，不是缺陷 |
| 预期偏差的量级 | 规划脚本 `_cfold_plan.py` 事先量化：`\|Δao\| ~ 1.4 / 0.8`（与实测 `[C:attn] 8.5~12`、`[D:o] 14~29` 同量级） |
| 为何最终仍 PASS | 同一份规划给出**归一化判据**：`E2E logits drift 0.14 < margin 2.03`——中间偏差传到 logits 只剩 0.14，而 top1 的判决余量是 2.03 |
| 判定移交到哪 | 该模式下 `C/D/U2` **仅报告 err、不计入 `fails`**，验收移交 **E2E logits 门** |

**一句话**：段级 FAIL 是中间量的**口径差异**（可预期、已量化），最终 PASS 是**端到端 logits 门的判决**——两者不是同一把尺子，混着看就会得出"自相矛盾"的错觉。

**注意：`fin` 阶段的门与上面不是同一套。** `C/D/U2` 由 `T23_E2EMODE` 控制（不设该变量时计入 `fails`），而 `fin`（phase 5）的 `[F:xnorm]` / `[F:top1]` 走的是**硬编码 `&rf`**——无论是否设置 `T23_E2EMODE`，都不计入 `fails`。**两套门不要混着读。**

依据：驱动源码 `tools/drivers/t23_m3p.c` 中 `fin` 的两处检查传的计数器是 `&rf`（约 1533-1535 行），而 `C/D/U2` 传的是 `e2e ? &rf : &fails`（如约 1908、1973、2146、2161 行）；`[F:top1]` 不匹配也只是 `rf++`（约 1589 行）。

依据出处：驱动源码 `tools/drivers/t23_m3p.c` 的 E2E 模式注释（约 1678-1680 行）。

## 9. 诚实的边界声明（接力前请知悉）

这些是从一开始就写进论文草稿、不能隐瞒的事实：

1. **不宣称密码学安全强度**：当前参数（`n=2048`、超长模数链）属**机制/正确性验证级**，远低于 128-bit；升级到 128-bit 需 `n ≥ 16384` 或等效参数。接力复现的是"**能不能算对**"，不是"**防不防得住**"。
2. **随机数是原型 RNG**，接口已预留 CSPRNG 注入位置，但当前未接入。
3. **权重是明文常量**（离线预处理好的 HE 明文），本链保护的是**推理输入与中间激活**，不是模型权重。把"全密文"理解为"输入与激活全密文"。
4. **性能不是卖点**：单 token 级延迟数小时，适合离线批处理/审计式隐私推理，不适合交互式生成。FHE 的代价是 10^5~10^7 量级的开销。
5. **28 层全链尚未跑完**：本文所有"28 层"表述均为**外推 ETA（≈50 h）**，不是实测值。

## 附录 A · 常见问题

**Q：`lay` 跑完没有 `RESULT=PASS`，但有 `CHAIN: dumped uL_*`？**
A：说明 dump 成功但校验没过，属真 FAIL，贴日志回 Issue。

**Q：能不能只跑 `lay` 不跑 `boot`？**
A：不行。`lay` 输出 `u{L}` 的噪声预算已接近耗尽，必须 `boot` 刷回满链（`out np=2083`）才能喂给下一层；否则下一层会**噪声击穿**。

**Q：`boot` 的 `in np=` 每层不同（如 15/16/20）正常吗？**
A：正常，这是上一跳 `lay` 消耗掉的模数链剩余量，取决于该层算子深度。只要 `out np=2083` 就说明刷新成功。

**Q：日志里中文变乱码？**
A：用 `cmd /c "... > file"` 重定向（不要走 PowerShell 管道）；`.ps1` 存 UTF-8 with BOM。

**Q：能在 ARM64/RK3588 上跑吗？**
A：可以。已验证与 x86 **逐系数位级一致**，可跨架构接力（但 RK3588 更慢，t0 段约 40 min，请自行评估）。

**Q：换台机器接着跑，精度会变吗？**
A：不会。位级一致性意味着结果与硬件舍入顺序解耦，跨机可复现。
