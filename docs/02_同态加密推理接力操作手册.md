# 同态加密推理接力操作手册

这份手册只讲怎么做，不展开讨论结论。目标是让接力者或验证者拿到仓库后，能按固定步骤完成：

1. 文件转换
2. 启动接力
3. 续跑接力
4. 独立验证
5. 归档打包

## 0. 路径口径（先读这条）

本文所有相对路径都以**开源仓库根**为起点：

```text
<reponame>/                       # 开源仓库根，即 kestrel-llm
├── src/core/                     # RNS-CKKS 引擎（vllm_ntt.c / vllm_ckks.c / vllm_tp.c）
├── tools/drivers/                # 层链驱动源码（t23_m3p.c / t23_chain.c）
├── tools/relay/                  # ← 本文所有脚本都在这里
├── .tmp_tok/                     # 数据与工作目录（需自行准备约 7 GB 数据包）
└── results/                      # 归档产物
```

三类路径不要混淆：

| 类别 | 位置 | 说明 |
|---|---|---|
| **工具脚本** | `tools/relay/` | 本手册操作的对象；脚本内部会自行定位仓库根 |
| **驱动/引擎源码** | `tools/drivers/`、`src/core/` | 编译时用 |
| **数据与产物** | `.tmp_tok/` | 引擎把数据路径硬编码到这里；`.gitignore` 已忽略，不入库 |

> 关于「在哪里运行」：**所有脚本都在仓库根目录运行**，但不必手动 `cd`。
> 脚本用「从自身所在目录向上找到含 `src/` 的目录」的方式自定位仓库根，
> 所以你从任意目录用 `-File <仓库>/tools/relay/xxx.ps1` 调用都能正确工作。

## 1. 主要工具一览

| 工具 | 作用 |
|---|---|
| `tools/relay/fix_crlf.sh` | 把代码树里的 `CRLF` 统一转成 `LF` |
| `tools/relay/rerun5_lay_boot.ps1` | 执行 `lay + boot` 接力，支持断点续跑 |
| `tools/relay/verify_layer.ps1` | 独立解密并做数值误差校验 |
| `tools/relay/layver_run.ps1` | 数值等价性验收（只换输入、不改线程数） |
| `tools/relay/collect_results.ps1` | 归档接力产物与日志 |
| `tools/relay/pack_relay.ps1` | 把交接物打成 zip 包 |
| `tools/relay/verify_relay.ps1` | 第三方验证收到的 zip 包 |
| `tools/relay/watch_relay.ps1` | 无人值守轮值：定时记状态、自动开跑、自动归档验证 |
| `tools/relay/_monitor.ps1` | 后台进度监控（辅助） |

- `tools/relay/verify_layer.c`
- `src/core/vllm_ckks.c`

- `.tmp_tok/l0/*`

还需要本机可直接调用：

- `gcc`
- `powershell`

## 3. 文件转换：先处理 CRLF

如果代码树是从 Windows 导出、再拷到 Linux 或板端环境，优先先做这一步。

`tools/relay/fix_crlf.sh` 的作用是把整棵代码树中的 `CRLF` 改为 `LF`，避免 `.sh` 报
`bad interpreter: /bin/bash^M`。

使用方式：

```bash
bash tools/relay/fix_crlf.sh              # 默认处理仓库根
bash tools/relay/fix_crlf.sh <目录>        # 处理指定目录
```

它只转换**文本文件**（`grep -I` 会跳过二进制），且 **`.git/` 一律不动**。执行后检查：

- `crlf_before` 是否大于 0
- `crlf_after` 是否变成 0

## 4. 启动接力

主入口是：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\relay\rerun5_lay_boot.ps1
```

它默认：

- 跑 `0..4` 层
- `T23_NT` 未设置时默认用 `4`
- `LayExe=.tmp_tok\t23lay.exe`
- `BootExe=.tmp_tok\t23boot.exe`
- `LogDir=.tmp_tok\relay_rerun`

如果你要显式指定二进制和日志目录，建议这样跑：

```powershell
$env:T23_NT = "4"
powershell -NoProfile -ExecutionPolicy Bypass -File tools\relay\rerun5_lay_boot.ps1 `
  -From 0 -To 4 `
  -LayExe .tmp_tok\t23lay.exe `
  -BootExe .tmp_tok\t23boot.exe `
  -LogDir .tmp_tok\relay_rerun
```

## 5. 接力脚本到底做了什么

`rerun5_lay_boot.ps1` 内部流程很固定：

1. 如果 `t23lay*.exe` / `t23boot*.exe` 不存在，就先用 `tools/drivers/` 的源码编译
2. 写 `meta.txt`
3. 从 `From..To` 逐层执行
4. 每层先 `lay`，再 `boot`
5. 若某一跳的 8 个 `.ct` 已齐全，则自动跳过
6. 最后写 `timing.tsv`

判据是：

- `lay` 日志里有 `RESULT=PASS`
- `boot` 日志里有 `BOOT=PASS`（且日志里 `out np=2083`，说明确实刷回了满链）

注意：**这两个都只表示流程走完、没有硬错误，不等于数值正确。** 脚本开了 `T23_E2EMODE=1`，
会把中间量偏差降级为"仅报告"（日志标 `[E2E:ref-deviate-ok]`），因此**浅层走错 SiLU 路径也会打 PASS**
（实测：层 0 缺 `silu0.bin` 时 `max|err|` = 4.2e-2 ~ 8.5e-2，仍报 `RESULT=PASS (0)`）。
**要判数值必须再跑 `verify_layer.ps1` 看 `max|err|`**（见 [`05_工具说明.md`](./05_工具说明.md) §5）。

### 段级 FAIL 但最终 PASS 的原因

跑起来后日志里会同时出现 `PASS` 和大量 `FAIL`，**这不是矛盾**。原因是两者量的不是同一件事：

| 环节 | 说明 |
|---|---|
| 段级为何 FAIL | L26/27 使用**真实 C 折叠**（`g_causal` + 实 C 折叠），中间量 `C/D/U2` 偏离真值**属预期**，不是缺陷 |
| 预期偏差的量级 | 规划脚本 `_cfold_plan.py` 事先量化：`\|Δao\| ~ 1.4 / 0.8`（与实测 `[C:attn] 8.5~12`、`[D:o] 14~29` 同量级） |
| 为何最终仍 PASS | 同一份规划给出**归一化判据**：`E2E logits drift 0.14 < margin 2.03`——中间偏差传到 logits 只剩 0.14，而 top1 的判决余量是 2.03 |
| 判定移交到哪 | 该模式下 `C/D/U2` **仅报告 err、不计入 `fails`**，验收移交 **E2E logits 门** |

**一句话**：段级 FAIL 是中间量的**口径差异**（可预期、已量化），最终 PASS 是**端到端 logits 门的判决**——两者不是同一把尺子，混着看就会得出"自相矛盾"的错觉。

**注意：`fin` 阶段的门与上面不是同一套。** `C/D/U2` 由 `T23_E2EMODE` 控制（不设该变量时计入 `fails`），而 `fin`（phase 5）的 `[F:xnorm]` / `[F:top1]` 走的是**硬编码 `&rf`**——无论是否设置 `T23_E2EMODE`，都不计入 `fails`。**两套门不要混着读。**

依据：驱动源码 `tools/drivers/t23_m3p.c` 中 `fin` 的两处检查传的计数器是 `&rf`（约 1533-1535 行），而 `C/D/U2` 传的是 `e2e ? &rf : &fails`（如约 1908、1973、2146、2161 行）；`[F:top1]` 不匹配也只是 `rf++`（约 1589 行）。

依据出处：驱动源码 `tools/drivers/t23_m3p.c` 的 E2E 模式注释（约 1678-1680 行）。

## 6. 如何续跑接力

这个脚本天生支持断点续跑。

例如：

- 如果 `lay0/boot0/lay1` 都已经完成
- 但 `boot1` 中断了

那么重新执行同一条命令时，它会自动跳过已经完整落盘的步骤，只从缺的那一跳继续。

继续跑后，关键日志在：

- `.tmp_tok\relay_rerun\master.log`
- `.tmp_tok\relay_rerun\lay*.out`
- `.tmp_tok\relay_rerun\boot*.out`

## 7. 如何监控接力

最直接看这几个文件：

- `.tmp_tok\relay_rerun\master.log`
- `.tmp_tok\relay_state\watch_relay_log.txt`
- `.tmp_tok\relay_state\watch_relay_decision.txt`

如果启用了 `watch_relay.ps1`，它会：

1. 每 15 分钟写一次状态
2. 读取 `.tmp_tok\relay_state\layver_result.txt`
3. 判据通过时自动启动接力
4. 接力结束后自动做归档、验证和位级比对

手动后台启动 watcher 的方式：

```powershell
Start-Process powershell -ArgumentList @(
  '-NoProfile',
  '-ExecutionPolicy','Bypass',
  '-File','tools\relay\watch_relay.ps1',
  '-From','0','-To','4',
  '-RefDir','.tmp_tok\chain_ref'
) -WorkingDirectory <仓库根> -WindowStyle Hidden
```

或者用轻量的进度监控：

```powershell
Start-Process powershell -ArgumentList '-NoProfile','-File','tools\relay\_monitor.ps1' -WindowStyle Hidden
Get-Content .tmp_tok\relay_rerun\_status.txt     # 每分钟自动刷新
```

## 8. 如何做数值等价性验收

如果你要回答的是：

> 「某个 boot 输出虽然位级不同，但后续 lay 是否仍然数值等价？」

那要跑 `layver_run.ps1`，不是只看 `BOOT=PASS`，也不是比字节相等。

使用方式：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\relay\layver_run.ps1 `
  -TargetLayer 1 `
  -AltDir .tmp_tok\chain\_alt_in `
  -BaselineLog .tmp_tok\relay_rerun\lay1.out `
  -NT 4
```

它做的事情是：

1. 备份当前 `u{L-1}r112*.ct` 与 `u{L}_*.ct`
2. 把 `-AltDir` 里的替代 `u{L-1}r112*.ct` 覆盖进链目录
3. 用 `T23_E2EMODE=1`、`T23_NT=-NT` 跑 `lay{L}`
4. 统计新的 `max|err|`
5. 和基线日志比较
6. 最后恢复现场

结果文件在：

```text
.tmp_tok\relay_state\layver_result.txt
```

通过口径：

- `RESULT=PASS`
- 且 `NEW max|err|` 与基线在同一量级/容差内

> **⚠️ `-TargetLayer` 必须 ≥ 1。**
> `lay0` 走的是「明文种子加密」分支，**不读任何链上密文**；把替代 `u0r112` 注入后跑 `lay0`
> 等于什么都没验证（两边统计必然相同）。要验收 `u0r112`，就要跑 `lay1`。

## 9. 如何做独立验证

`verify_layer.ps1` 是第三方口径，不复用驱动自己的 PASS 判据。

### 9.1 校验 lay 输出

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\relay\verify_layer.ps1 `
  -From 0 -To 4 -Mode lay
```

### 9.2 校验 boot 输出

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\relay\verify_layer.ps1 `
  -From 0 -To 4 -Mode boot
```

默认容差：

```text
Tol = 3e-2
```

返回码解释：

- `0`：全部通过
- 非 `0`：失败层数

## 10. 如何归档结果

接力跑完后，用：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\relay\collect_results.ps1 `
  -From 0 -To 4 `
  -LogDir .tmp_tok\relay_rerun `
  -Dest results\L0-4
```

会归档：

- `chain/u{L}_*.ct`
- `chain/u{L}r112_*.ct`
- `logs/lay{L}.out/.err`
- `logs/boot{L}.out/.err`
- `meta.txt`
- `timing.tsv`
- `master.log`
- `manifest.sha256`

## 11. 如何打包给下一个接力者

如果你要把某一段层范围交给别人续跑，用：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\relay\pack_relay.ps1 `
  -From 0 -To 4 -Id yourname
```

默认输出：

```text
.tmp_tok\relay_out\relay_L0-4_yourname_<时间戳>.zip
```

包里包括：

- `chain/`：核心交接密文 `u{L}r112_*.ct`
- `logs/`
- `timing.tsv`
- `meta.txt`
- `master.log`
- `manifest.sha256`
- `README.txt`
- `sk.bin`（默认包含）

如果不想带私钥：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\relay\pack_relay.ps1 `
  -From 0 -To 4 -Id yourname -NoKey
```

## 12. 如何验证收到的交接包

收到 zip 后，用：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\relay\verify_relay.ps1 `
  -Zip <包路径>
```

它会检查三件事：

1. `manifest.sha256` 是否和包内文件逐一匹配（并反向检查有无夹带未收录文件）
2. `lay*.out` 是否含 `RESULT=PASS`
3. `boot*.out` 是否含 `BOOT=PASS` 且有足够的 `out np=2083`

返回码：

- `0`：全部通过
- `1`：至少一个检查项失败

## 13. 推荐的标准操作顺序

推荐固定按下面顺序来，最不容易漏步骤：

1. 如有跨平台导出，先跑 `tools/relay/fix_crlf.sh`
2. 确认 `.tmp_tok/chain/sk.bin`、`.tmp_tok/l0/*`、参考明文都在
3. 设定 `T23_NT`
4. 跑 `tools/relay/rerun5_lay_boot.ps1`
5. 跑 `tools/relay/verify_layer.ps1 -Mode lay`
6. 跑 `tools/relay/verify_layer.ps1 -Mode boot`
7. 跑 `tools/relay/collect_results.ps1`
8. 如需交接，再跑 `tools/relay/pack_relay.ps1`
9. 接收方收到包后跑 `tools/relay/verify_relay.ps1`

## 14. 常见误区

### 14.1 误区：`BOOT=PASS` 就等于数值通过

不是。  
`BOOT=PASS` 只表示 boot 驱动本身没有在 `load / refresh / save` 上失败。

### 14.2 误区：线程数不同但 PASS，就说明位级一致

也不是。  
这轮已经证明：

- `NT=4` 与 `NT=8` 可以都 PASS
- 但输出 `.ct` 仍然可能位级不同

### 14.3 误区：只保留 `.ct` 文件就够了

不够。  
接力至少还需要：

- 对应日志
- `meta.txt`
- `timing.tsv`
- `manifest.sha256`

否则别人无法独立判断你到底跑到了哪一步、用的是什么口径。

### 14.4 误区：注入替代输入后随便挑一层跑，就能验收等价性

不是。  
层号与它读的输入是绑定的：`lay{L}` 读 `u{L-1}r112`。挑错层（比如拿 `u0r112` 去跑 `lay0`）
会得到一个「两边完全相同」的假通过。
