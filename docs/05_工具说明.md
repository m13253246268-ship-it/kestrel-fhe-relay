# 工具说明 · RNS-CKKS 密文链工具链

> 面向：接力者（跑层）、验证者（收包复核）、复现者（从种子复现）。
> 配套：流程与判据见 [`04_接力复现指南.md`](./04_接力复现指南.md)。
> 版本：2026-09-14 · 全部脚本**一律在仓库根目录运行**。

**工具在主仓，数据在工作目录**

| 位置 | 用途 |
|---|---|
| `<主仓>/tools/relay/` | **脚本与驱动（正式副本）**：跑层 / 打包 / 验包 / 复核脚本，以及 `t23_m3p.c` / `t23_chain.c` / `verify_layer.c` 源码 |
| `<主仓>/src/core/` | 引擎内核 `vllm_ntt.c` / `vllm_ckks.c` / `vllm_tp.c`（编译时链接） |
| `.tmp_tok/` | **工作目录**：脚本假定 cwd 下有 `.tmp_tok/`（数据包解压处），密文/日志都落在这里 |

## 0. 工具总览

| 工具 | 作用（一句话） | 关键参数 | 主要产物 | 退出码 |
|---|---|---|---|---|
| `rerun5_lay_boot.ps1` | **跑层**：逐层 `lay`+`boot`，支持断点续跑 | `-From -To` | `.tmp_tok/chain/*.ct`、`relay_rerun/{lay,boot}*.out`、`timing.tsv` | 0=完成 |
| `pack_relay.ps1` | **打包**：把某层范围成果打成可上传 zip | `-From -To -Id` | `.tmp_tok/relay_out/*.zip`（内含 manifest + README） | 0=成功 |
| `verify_relay.ps1` | **验包**：校验 zip 的完整性 + 判据 + 结构 | `-Zip` | 控制台 PASS/FAIL 明细 | 失败项数 |
| `verify_layer.exe` / `.ps1` | **验算**：解密对明文参考，判"算得对不对" | `-L`/`-From -To` | `max\|err\|` + PASS/FAIL | 失败层/项数 |
| `_monitor.ps1` | 后台进度监控（辅助） | 无 | `relay_rerun/_status.txt` | — |

三个二进制：`t23lay.exe`（np=112）、`t23boot.exe`（np=2100）、`verify_layer.exe`（np=112）。

## 1. 前置：构建三个二进制

> **不想装 gcc**：本仓 **Releases** 里有这三个二进制的预编译 Windows x86-64 版（**静态链接、免装 MinGW**）。
> 解压后放进 `<仓库根>\.tmp_tok\` 即可**整节跳过**；见 [`data/README.md`](../data/README.md) §3 ⓪。
> 非 Windows 平台请照下面的命令自建。
> 构建前先 `New-Item -ItemType Directory -Force .tmp_tok, .tmp_tok\chain`——`.tmp_tok` 不存在时链接器会报
> `cannot open output file`，`.tmp_tok\chain` 不存在时驱动会报 `[FAIL] ct save`（**驱动不会自建目录**）。
> 用 `rerun5_lay_boot.ps1` 则不用手建，脚本会自己准备好这两个目录。

```powershell
# ① lay 驱动（层内前向，模数链 112 素数）
gcc -O2 -fopenmp -Wno-implicit-function-declaration `
    -I include -I include/core -I include/common `
    -DCKKS_N=2048 -DCKKS_NPRIMES=112 -DBB=32 -DGG=32 `
    src/core/vllm_ntt.c src/core/vllm_ckks.c src/core/vllm_tp.c tools/drivers/t23_m3p.c `
    -o .tmp_tok/t23lay.exe -lm

# ② boot 驱动（噪声刷新，2100 素数；大栈必需）
gcc -O2 -fopenmp -Wno-implicit-function-declaration '-Wl,--stack,33554432' `
    -I include -I include/core -I include/common `
    -DCKKS_N=2048 -DCKKS_NPRIMES=2100 -DBB=32 -DGG=32 `
    src/core/vllm_ntt.c src/core/vllm_ckks.c src/core/vllm_tp.c tools/drivers/t23_chain.c `
    -o .tmp_tok/t23boot.exe -lm

# ③ 独立验证器（np=112 即可覆盖 lay 输出与刷新后密文）
gcc -O2 -fopenmp -Wno-implicit-function-declaration `
    -I include -I include/core -I include/common `
    -DCKKS_N=2048 -DCKKS_NPRIMES=112 -DBB=32 -DGG=32 `
    src/core/vllm_ntt.c src/core/vllm_ckks.c src/core/vllm_tp.c tools/relay/verify_layer.c `
    -o .tmp_tok/verify_layer.exe -lm
```

**构建坑（都踩过）**
1. `-I` 必须同时给 `include`、`include/core`、`include/common`（`vllm_tp.c` 依赖 `common/vllm_platform.h`）。
2. PowerShell 下 `-Wl,--stack,...` 的**逗号会被当作参数分隔符** → 整段加引号 `'-Wl,--stack,33554432'`。
3. `boot`（np=2100）必须加大栈，否则 MinGW 下 `0xC00000FD` 栈溢出。
4. 含中文注释的 `.ps1` 必须存为 **UTF-8 with BOM**，否则 PowerShell 5.1 按 ANSI 读会报"意外的标记 }"。

## 2. `rerun5_lay_boot.ps1` — 跑层（断点续跑）

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/relay\rerun5_lay_boot.ps1 -From 5 -To 7
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `-From` | 0 | 起始层号（含） |
| `-To` | 4 | 结束层号（含） |
| `$env:T23_NT` | 4 | 线程数（环境变量，非参数） |

**行为**
- 每层依次跑 `lay`（`u{L-1}r112 → u{L}`）与 `boot`（`u{L} → u{L}r112`）；
- **断点续跑**：某跳的输出 8 个 `.ct` 齐全即跳过；中途中断后重跑同一命令即可接着算；
- 任一跳失败即中止并记录（不会带着坏结果继续）。

**产物**

| 路径 | 内容 |
|---|---|
| `.tmp_tok/chain/u{L}_{t}_{h}.ct` | lay 输出（8 个/层） |
| `.tmp_tok/chain/u{L}r112_{t}_{h}.ct` | **boot 输出 = 交给下一棒的交接物** |
| `.tmp_tok/relay_rerun/master.log` | 逐跳时间线（含 PASS/FAIL 与耗时） |
| `.tmp_tok/relay_rerun/lay{L}.out` / `boot{L}.out` | 原始日志（判据证据） |
| `.tmp_tok/relay_rerun/timing.tsv` | 逐层耗时汇总 |
| `.tmp_tok/relay_rerun/meta.txt` | 机器/编译器/线程元数据 |

**判据**：`lay` 看日志末尾 `RESULT=PASS`；`boot` 看 `BOOT=PASS` 且 `out np=2083`（每层 8 次）。**段级 A/B/C/D 的 FAIL 不算数**（见指南 §7）。

## 3. `pack_relay.ps1` — 打包交接

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/relay\pack_relay.ps1 -From 5 -To 7 -Id yourname
```

| 参数 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `-From` | ✅ | — | 起始层号 |
| `-To` | ✅ | — | 结束层号 |
| `-Id` | | `anon` | 打包者标识（进包名与 README） |
| `-LogDir` | | `.tmp_tok\relay_rerun` | 日志目录 |
| `-ChainDir` | | `.tmp_tok\chain` | 密文目录 |
| `-NoKey` | | 关 | 排除 `sk.bin`（接收方须自行持有同一私钥） |

**包内结构**

```
relay_L5-7_yourname_<时间戳>/
├── chain/    u{L}r112_{t}_{h}.ct ×8 × 每层      ← 核心交接物
├── logs/     lay{L}.out/.err  boot{L}.out/.err  ← 判据证据
├── timing.tsv  meta.txt  master.log
├── sk.bin                                        ← 全链共用私钥
├── manifest.sha256                               ← 包内每个文件的 SHA256
└── README.txt                                    ← 层范围/主张边界/验证与续跑
```

**体积**：1 层 ≈28 MB；4 层 ≈111 MB（实测）。输出会打印 zip 的 SHA256，作为对外发布凭据。

## 4. `verify_relay.ps1` — 验证交接包

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/relay\verify_relay.ps1 -Zip .tmp_tok\relay_out\relay_L5-7_x_20260914-1200.zip
```

| 参数 | 必填 | 说明 |
|---|---|---|
| `-Zip` | ✅ | 待校验的包路径 |
| `-Keep` | | 保留解包目录（默认自动清理） |

**三类检查**

| # | 检查 | 判定 |
|---|---|---|
| ① | 完整性 | 包内每个文件 SHA256 与 `manifest.sha256` 一致；**并反向检查是否夹带 manifest 未收录的文件** |
| ② | 判据 | `logs/lay*.out` 含 `RESULT=PASS`；`logs/boot*.out` 含 `BOOT=PASS` 且 `out np=2083` 恰好 8 次 |
| ③ | 结构 | 每层 8 个 `u{L}r112_*.ct`，单文件 ≈3.5 MB（np=112） |

**样例输出**（本仓库自测）

```
[1] integrity   [PASS] all files match manifest -- checked=51 mismatched=0
                [PASS] no unlisted files (no smuggling) -- 0 extra
[2] criteria    [PASS] lay criterion lay0..lay3
                [PASS] boot criterion boot0..boot3 -- BOOT=PASS=True refreshes=8
[3] structure   [PASS] ciphertexts present -- count=32   [PASS] each ct ~3.5MB
RESULT: ALL_CHECKS_PASS
```

**信任边界（必须说清）**
- ✅ 能证明：包**没被篡改 / 截断 / 夹带**，且密文与判据日志是同一批产物。
- ⚠️ **不能**证明"计算本身是对的"——判据日志理论上可伪造。要判正确性请用 §5，要防伪造请用 §5 的**位级交叉复算**。

## 5. `verify_layer` — 判"算得对不对"（准确度校验）

### 5.1 原理

`sk.bin` 解密该层密文 → 解码成实数槽位 → 与 **float32 明文前向**产生的参考 `tail/l{L}_u2_ref.bin` 逐元素对照，算 `max|err|`。
这是一条**独立于驱动 PASS 判据的代码路径**（自行实现解密/解码/对照），因此可作第三方复核。

> 前提：FHE **没有免密钥的通用正确性验证**；"算得对"只能靠"解密后对明文参考"。所以包里必须有 `sk.bin`，且验证方需持有数据包中的参考 `tail/l{L}_u2_ref.bin`。

### 5.2 用法（批量封装）

```powershell
# ① 校验 lay 输出 u{L}（默认容差 3e-2）
powershell -NoProfile -ExecutionPolicy Bypass -File tools/relay\verify_layer.ps1 -From 0 -To 4
# ② 校验 boot 刷新输出 u{L}r112
powershell -NoProfile -ExecutionPolicy Bypass -File tools/relay\verify_layer.ps1 -From 0 -To 3 -Mode boot
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `-From` / `-To` | 0 / 4 | 层范围 |
| `-Mode` | `lay` | `lay` = 校验 `u{L}`；`boot` = 校验 `u{L}r112` |
| `-ChainDir` | `.tmp_tok\chain` | 密文目录 |
| `-Sk` | `<ChainDir>\sk.bin` | 私钥路径 |
| `-Tol` | `3e-2` | 判定容差 |
| `-Exe` | `.tmp_tok\verify_layer.exe` | 底层程序（缺失时自动构建） |

### 5.3 用法（底层程序，含位级交叉复算）

```powershell
# 单项准确度
.tmp_tok\verify_layer.exe -L 4 -Dir .tmp_tok/chain -Sk .tmp_tok/chain/sk.bin -Tol 3e-2

# 位级交叉复算（防伪造）：两人独立跑同一层，逐字节比对
.tmp_tok\verify_layer.exe -BitA u5 -BitB u5_other -L 5
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `-L` | 4 | 层号 |
| `-Ct` | `u{L}` | 密文前缀（如 `u4`、`u4r112`） |
| `-Ref` | `.tmp_tok/tail/l{L}_u2_ref.bin` | 明文参考（8192 个 float32） |
| `-Tol` | `3e-2` | 容差 |
| `-Scale` | 1.0 | 参考缩放因子 |
| `-Dir` | `.tmp_tok/chain` | 密文目录 |
| `-Sk` | `.tmp_tok/chain/sk.bin` | 私钥路径 |
| `-BitA` / `-BitB` | — | 位级比对的两组前缀（须成对给出） |

### 5.4 工具自身的标定（用旧一轮真实数据，逐层吻合）

| 层 | `verify_layer` 实测 `max\|err\|` | 驱动日志 `.tmp_tok/relay/lay{L}.out` | 一致 |
|---|---|---|---|
| 0 | 1.2712e-03 | 1.271e-03 | ✅ |
| 1 | 3.1467e-03 | 3.147e-03 | ✅ |
| 2 | 2.8366e-02 | 2.837e-02 | ✅ |
| 3 | 1.2284e-02 | 1.228e-02 | ✅ |
| 4 | 1.3820e-02 | 1.382e-02 | ✅ |

5 层全部对上（4–5 位有效数字）⇒ 工具与驱动等价；结论 **`ALL_LAYERS_VERIFY_PASS`**。

### 5.5 ⚠️ 已知发现：误差余量并不宽裕

- 层 2 的 `t1 h1` 分量 `max|err| = 2.837e-02`，容差 `3e-2` —— **只剩 5.8% 余量**；层 2 另有 1.93e-02 / 1.52e-02。
- 规律：**误差系统性集中在 `h=1` 分量**（维度 1024–2047），`h=0` 通常小一个数量级。
- 含义：前 5 层通过成立，但**深层可能吃紧**。接力第 6 层起应逐层记录 `h=1` 的 `max|err|` 趋势。
- **剩余信任缺口**：参考 `tail/l{L}_u2_ref.bin` 目前来自作者的明文管线；若要连参考也独立，需用 numpy 从原始权重重算 float32 前向并替换该文件。

## 7. 三种角色的典型工作流

**接力者（跑 N 层 → 提交）**
```powershell
# 1) 确认输入就位：u{L-1}r112_*.ct 在 chain/ 且 tail/w{L}/ 存在
# 2) 跑
powershell -NoProfile -ExecutionPolicy Bypass -File tools/relay\rerun5_lay_boot.ps1 -From 5 -To 7
# 3) 自检准确度（可选，需数据包参考）
powershell -NoProfile -ExecutionPolicy Bypass -File tools/relay\verify_layer.ps1 -From 5 -To 7
# 4) 打包提交
powershell -NoProfile -ExecutionPolicy Bypass -File tools/relay\pack_relay.ps1 -From 5 -To 7 -Id yourname
```

**验证者（收包复核）**
```powershell
# 1) 先核 zip 的 SHA256（发布方公布值）
Get-FileHash .tmp_tok\relay_out\relay_L5-7_x.zip -Algorithm SHA256
# 2) 包内逐字节 + 判据 + 结构
powershell -NoProfile -ExecutionPolicy Bypass -File tools/relay\verify_relay.ps1 -Zip <包>
# 3) 有数据包则可进一步判"算得对"
powershell -NoProfile -ExecutionPolicy Bypass -File tools/relay\verify_layer.ps1 -From 5 -To 7
# 4) 关键层防伪造：第二人独立复算后位级比对
.tmp_tok\verify_layer.exe -BitA u7 -BitB u7_independent -L 7
```

**复现者（从种子复现 L0–4）**
```powershell
# 前置：备份并清空 chain/ 的 *.ct（保留 sk.bin）
powershell -NoProfile -ExecutionPolicy Bypass -File tools/relay\rerun5_lay_boot.ps1 -From 0 -To 4
powershell -NoProfile -ExecutionPolicy Bypass -File tools/relay\verify_layer.ps1 -From 0 -To 4
```

## 8. 通用约定与坑

| 项 | 约定 |
|---|---|
| 工作目录 | 全部脚本以**仓库根**为 cwd（脚本内部自动 `Set-Location` 到根） |
| 编码 | 含中文的 `.ps1` 存 **UTF-8 with BOM**；子进程输出用 `cmd /c "... > out 2> err"` 重定向（避免 PowerShell 管道把 UTF-8 中文转成乱码） |
| 判据 | 层输出判据是 `RESULT=PASS` / `BOOT=PASS`（段级 A/B/C/D 的 `FAIL` 是参考口径产物，不作为结论）；**判据 ≠ 数值通过**，数值须另跑 §5 的 `verify_layer` |
| 断点语义 | 某跳输出 8 个 `.ct` 齐全即视为完成并跳过 |
| 交接物 | 每层 8 个 `u{L}r112_{t}_{h}.ct`（≈28 MB/层）+ `sk.bin` |
| 确定性 | 同源数据 + 同源二进制 + 相同层序 ⇒ 逐字节一致（支持跨机、跨 ISA 交叉复算） |
